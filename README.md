# QuietChat

Статическое приложение для локального шифрования текста, фотографий и коротких голосовых сообщений. Откройте приложение, выберите проверенного собеседника и передайте получившийся текстовый контейнер удобным способом. QuietChat сам ничего никому не отправляет.

В проекте нет аккаунтов, backend, аналитики, телеметрии, удалённых шрифтов, CDN, сетевых кодеков или облачной обработки. Браузер получает только статические файлы приложения. Ключи и содержимое обрабатываются локально; для криптографии используется включённая в сборку `libsodium-wrappers-sumo`.

**Это новый проект без независимого аудита.** Он не обещает абсолютную анонимность, прямую секретность, постквантовую защиту или свойства Signal. [Модель угроз и ограничения](docs/SECURITY.md), [точный формат контейнера и резервной копии](docs/FORMAT.md).

## Быстрый запуск на компьютере

Нужен Node.js 22 или новее; GitHub Actions использует Node.js 24. Все версии npm-зависимостей зафиксированы, транзитивные зависимости включены в `package-lock.json`.

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run build
npm run preview
```

Откройте `http://127.0.0.1:4173/`. Сервер предпросмотра слушает только loopback, раздаёт только `dist/`, не принимает загрузки и не ведёт журналы запросов. Это инструмент разработки, он не нужен на GitHub Pages. Не открывайте `index.html` через `file://`: Worker, микрофон и PWA требуют подходящего безопасного контекста — HTTPS или localhost.

Для браузерных проверок:

```sh
npx --no-install playwright install chromium
npm run test:browser
```

На Linux для первого запуска может понадобиться `npx --no-install playwright install --with-deps chromium`. Загрузка npm-пакетов и тестового браузера происходит **на этапе разработки**, а не во время работы приложения с сообщениями.

Проверка размещения в подпапке:

```sh
node scripts/serve.mjs --port 4174 --base /QuietChat/
```

Откройте `http://127.0.0.1:4174/QuietChat/`. Сборку менять не нужно: пути к скриптам, стилям, Worker, иконкам, manifest и service worker относительные.

## Публикация на GitHub Pages

1. Создайте репозиторий, например `QuietChat`, и добавьте исходники, включая `package-lock.json` и `.github/workflows/pages.yml`. Не добавляйте ключи, резервные копии, реальные сообщения и частные медиа. Папки `dist/` и `node_modules/` не нужны в Git.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**. Сайт рассчитан на GitHub.com; для GitHub Enterprise отдельно проверьте поддержку Pages Actions.
3. Основная ветка в workflow называется `main`. Если у вас другое имя, измените фильтры ветки и условия публикации в workflow.
4. Отправьте изменения в `main`. Workflow выполняет `npm ci`, модульные тесты, сборку и Chromium-проверки. Публикация начинается только после их успеха. Pull request запускает проверки без публикации.
5. В **Actions → Test and publish QuietChat → deploy** откройте адрес сайта. Обычно это `https://ВАШ_ЛОГИН.github.io/QuietChat/`. Используйте HTTPS и адрес с завершающим `/`.
6. Дождитесь подтверждения «Офлайн готов», затем закройте приложение и проверьте повторное открытие с отключённой сетью. В Safari на iPhone можно добавить сайт на экран «Домой», в Android/настольном браузере — воспользоваться установкой приложения, если браузер её предлагает.

Workflow имеет `contents: read` по умолчанию. Только задание публикации получает `pages: write` и `id-token: write`; постоянный PAT не нужен. GitHub Actions закреплены полными SHA, checkout не сохраняет учётные данные. В Pages передаётся только `dist/`, включая служебный статический `.nojekyll`.

Официальная справка: [пользовательские workflow GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). Защитите `main` и окружение `github-pages`, ограничьте право изменять исходники/workflow и проверяйте обновления зависимостей. Закрепление версий ограничивает неожиданные изменения, но само по себе не доказывает безопасность кода.

## Первый обмен ключами

1. Каждый участник самостоятельно открывает **Мои ключи → Создать пару ключей** на своём устройстве. Секретный ключ не передают другому человеку.
2. Сразу создайте зашифрованную резервную копию. Иначе блокировка, перезагрузка или закрытие вкладки уничтожат единственную доступную приложению копию несохранённых ключей.
3. Передайте друг другу только строку открытого ключа `QCP1.…` или скачанный файл открытого ключа.
4. В **Контакты** введите своё локальное имя собеседника и его открытый ключ; можно импортировать `.txt`.
5. Сверьте **полный отпечаток** с владельцем ключа по независимому доверенному каналу — например, при личной встрече. Сравнение через тот же потенциально подменённый чат недостаточно. После сверки явно отметьте контакт проверенным.
6. Зашифрование и расшифрование доступны только с проверенным контактом. При замене ключа приложение предупреждает и сбрасывает подтверждение: новый отпечаток нужно сверить заново.

Отпечаток — полный 256-битный BLAKE2b с разделением домена, а не короткий идентификатор. Имена контактов не участвуют в криптографии. Они нужны только вам и не включаются в наружные поля сообщений. Контейнер не содержит открытого ключа отправителя: при получении выберите отправителя вручную.

## Текст, изображение и голос

**Текст.** В **Зашифровать** выберите получателя, вкладку **Текст** и введите сообщение. Русский язык, Unicode и emoji поддерживаются; ограничение считается в байтах UTF-8. Нажмите **Зашифровать**, затем явно скопируйте контейнер или скачайте `.txt`.

**Изображение.** Выберите вкладку **Изображение**, файл PNG/JPEG/WebP или нажмите **Вставить из буфера**. Разрешение на чтение буфера запрашивается только по действию пользователя; при ограничениях браузера используйте выбор файла. Внешние URL не загружаются. По умолчанию создаётся приватная копия: приложение декодирует растр и заново сохраняет пиксели, без исходного имени, EXIF/GPS/XMP, комментариев и других исходных файловых тегов. Предпросмотр показывает именно данные, которые будут зашифрованы. Если подготовка не удалась, операция завершается ошибкой; молчаливой отправки исходника нет.

Приватная картинка — PNG, в котором оставлены только блоки IHDR/IDAT/IEND. Повторное кодирование может изменить качество, цвет и ориентацию. Анимированные PNG/WebP, HEIC, SVG, HTML и нераспознанные форматы отклоняются, облачной конвертации нет. Режим **Сохранить оригинал без изменений** включается только явно и сохраняет потенциально чувствительные метаданные. Даже чистый файл может содержать лица, документы и адреса на самих пикселях.

**Голос.** Выберите **Голос → Записать голос**. Доступ к микрофону нужен только после нажатия. Во время записи виден индикатор. Остановите запись, прослушайте подготовленный WAV, при необходимости удалите его, затем зашифруйте. Запись ограничена 60 секундами. Все дорожки микрофона останавливаются при завершении, отмене, блокировке и уходе приложения в фон. Запись использует локальный AudioWorklet и совместимый PCM WAV, без загрузки кодеков. Если необходимые браузерные возможности отсутствуют, используйте импорт поддерживаемого аудиофайла.

**Импорт аудио.** Выберите аудиофайл. По умолчанию создаётся новая копия PCM WAV из декодированных отсчётов, без исходного имени, обложки и тегов. Такой файл больше сжатого оригинала. Разрешены PCM WAV, MP3 Layer III, Ogg/Opus, ограниченный однотрековый WebM/Opus без lacing и нефрагментированный MP4/AAC только со звуком. MP4 допускается только с AAC-LC без расширений, внешних ссылок и нескольких дорожек; число отсчётов ограничивается независимо от заявленной длительности. Это ограниченный набор проверяемых структур, а не обещание принять любой файл с таким расширением. Для сжатого импорта предел 4 МиБ; для WAV — 8 МиБ. Если декодирование не поддерживается или проверка структуры/ресурсов не проходит, приложение сообщает об этом; автоматического переключения на исходник нет. Возможности декодирования исходного формата зависят от браузера. Голос и фоновые звуки могут раскрывать личность и обстановку даже после удаления метаданных.

## Получение и части контейнера

1. Восстановите свои ключи из резервной или локальной зашифрованной копии.
2. Откройте **Расшифровать**, вручную выберите проверенного отправителя.
3. Вставьте контейнер `QC1.…` или импортируйте `.txt`. Пробелы и переносы строк допускаются.
4. Нажмите **Расшифровать**. Приложение сначала проверяет весь поток, порядок блоков и обязательный финальный тег. При любой ошибке содержимое не показывается и не воспроизводится.
5. Текст выводится как текст, без HTML/Markdown. Изображения и звук доступны в локальном просмотре. Сохранение и копирование возможны только по явной кнопке. Результат не сохраняется в историю.

Для длинного контейнера нажмите **Разделить на части**. У частей есть идентификатор набора, номер, общее количество и контрольная сумма от опечаток. Получатель вставляет все части одного набора; порядок поступления не важен. Пропуски, конфликтующие повторения и смешение разных наборов отклоняются. После сборки обязательно выполняется полная криптографическая проверка: номера и контрольная сумма её не заменяют.

Группировка доступна для контейнеров до 64 КиБ. Группировка по пять символов помогает при ручном переписывании короткого текста. У медиа шифротекст очень длинный; обычно удобнее `.txt`. Base64url — транспортное кодирование, не защита: оно увеличивает объём примерно на треть ещё до служебных данных и дополнения. Интерфейс показывает конечный размер.

## Резервные копии и локальное хранилище

В **Мои ключи** задайте длинную уникальную парольную фразу (минимум 12 символов) и повторите её. **Скачать резервную копию** создаёт файл `QCB1.…` с ключевой парой и текущими контактами внутри шифрования. Храните его отдельно от парольной фразы. Проверьте восстановление на тестовом профиле, прежде чем полагаться на копию.

Для восстановления выберите файл, введите пароль и нажмите **Восстановить выбранную копию**. Перед восстановлением другого профиля заблокируйте текущий, предварительно сохранив его резервную копию. Неверный пароль и повреждённый файл не раскрывают частичный результат. Нельзя восстановить потерянный секретный ключ из открытого ключа. Забытую парольную фразу восстановить некому.

**Сохранить на этом устройстве** — отдельное добровольное действие. В постоянное хранилище записывается только зашифрованный контейнер резервной копии. Пароль, разблокированные ключи, имена и открытые ключи контактов по отдельности не сохраняются. Локальная копия — снимок на момент нажатия: после изменения контактов сохраните её заново. **Удалить локальную копию** удаляет запись приложения; это не обещание физического стирания с накопителя или резервных копий браузера.

Argon2id v1.3 получает ключ из пароля с **64 МиБ памяти и opslimit=3**; XChaCha20-Poly1305 шифрует резервную копию. Для каждого сохранения создаются новые криптографически случайные соль и nonce. 64 МиБ — намеренный компромисс для телефонов; 3 прохода повышают стоимость перебора и могут занять несколько секунд. На слабых устройствах операция может быть недоступна. Параметры не снижаются автоматически; импорт принимает только документированный профиль до запуска дорогого KDF. Дорогая криптография выполняется в Worker, отмена завершает Worker и очищает сеанс.

## Блокировка и офлайн

**Заблокировать и очистить** завершает сеанс, останавливает запись и воспроизведение, очищает поля, контакты и доступные буферы, отзывает object URL и завершает криптографический Worker. Автоблокировка срабатывает через 5 минут бездействия и при уходе в фон. Заранее сохраните зашифрованную резервную копию ключей. Пароли не сохраняются. Сообщения, черновики, оригиналы и расшифрованные результаты существуют только в памяти до очистки; файлы сохраняются лишь по вашей кнопке.

JavaScript не даёт гарантированного стирания всех копий памяти. Браузер может задержать фоновое событие или успеть сделать снимок окна для переключателя приложений. ОС, клавиатура, расширения, swap и дампы могут сохранять данные за пределами контроля сайта. Перед уходом нажимайте блокировку. Автозамена и проверка орфографии отключены там, где это позволяет браузер; клавиатурой ОС сайт не управляет. Буфер обмена может синхронизироваться между устройствами — копируйте содержимое осознанно.

После полной загрузки service worker скачивает только фиксированный список файлов сборки и проверяет SHA-256 каждого. Статус **Офлайн готов** появляется только после проверки всего кэша той же версии. Это проверка полноты кэша, **не независимое доказательство подлинности кода**. Браузер может удалить кэш, особенно при нехватке места или в приватном режиме. Проверяйте офлайн-запуск до важного сеанса. При утрате кэша понадобится снова загрузить приложение; резервная копия ключей должна существовать независимо от браузера.

Для строгого офлайн-сеанса сначала дождитесь готовности, затем отключите Wi-Fi и мобильные данные средствами устройства. Переключатель внутри сайта не мог бы гарантировать отсутствие активности браузера, ОС или расширений. QuietChat такого обещания не делает.

Новая версия устанавливается в ожидании, но не активируется посреди открытого сеанса: service worker не использует `skipWaiting()`. При первом посещении уже активный worker берёт страницу под контроль через `clients.claim()` только после проверки совпадения версии и всего кэша; до этого создание и разблокировка ключей недоступны. Это исключает первый сеанс вне контроля закреплённой версии и не активирует ожидающее обновление. Для обновления сохраните ключи, заблокируйте приложение, **закройте все его вкладки и окна PWA**, затем откройте снова. Автоматической перезагрузки нет. Версия в интерфейсе содержит номер пакета и хеш исходных файлов. Если после повреждения кэша возникает ошибка загрузки, закройте все вкладки и откройте сайт онлайн; при необходимости удалите данные сайта только после сохранения зашифрованной резервной копии.

## Криптография и утечки размера

Для каждой операции создаётся новый случайный 256-битный ключ содержимого. `crypto_secretstream_xchacha20poly1305` шифрует поток блоками по 64 КиБ. Ключ передаётся в аутентифицированном конверте `crypto_box_easy`, используя секретный ключ отправителя и открытый ключ получателя. Конверт связывает ключ с версией и заголовком потока, а каждый блок использует дополнительные аутентифицированные данные с полным наружным префиксом, упорядоченной парой локально известных открытых ключей и индексом. Это защищает от перестановки и склейки частей разных контейнеров, а также отражения исходящего сообщения обратно отправителю. Открытые ключи в контейнер при этом не записываются. [Побайтовая спецификация](docs/FORMAT.md) описывает все поля, проверки и границы.

Тип содержимого, MIME и длина находятся внутри шифрования. Снаружи нет имён контактов, времени записи, ключей участников или постоянного идентификатора. Длина всё же приблизительно видна: до 1 КиБ полезные данные дополняются до интервала 256 байт, до 64 КиБ — 4 КиБ, далее — 256 КиБ. При чтении допустимое дополнение ограничено. Дополнение не скрывает общий порядок размера или корреляцию сообщений.

`crypto_box` аутентифицирует пару участников, но не создаёт цифровую подпись и доказательство авторства для третьих лиц. **Прямой секретности нет:** компрометация долговременного секретного ключа любой стороны вместе с известным открытым ключом другой стороны позволяет раскрывать ранее перехваченные контейнеры. Случайный ключ каждого сообщения и secretstream сами по себе этого не исправляют. Повторная доставка старого корректного контейнера не считается криптографической ошибкой: приложение не хранит историю или базу повторов.

## Ограничения ресурсов

| Данные | Ограничение |
| --- | --- |
| Текст | 65 536 байт UTF-8 |
| Исходный и подготовленный файл | 8 МиБ |
| Изображение | 12 000 000 пикселей, максимум 8192 по каждой стороне |
| Сжатое импортируемое аудио | 4 МиБ |
| Запись/импорт аудио | 60 секунд; импорт до 2 каналов, 8–96 кГц; MP4/AAC консервативно короче |
| Приватный звук | PCM WAV 16 bit, до 2 каналов, 32 кГц после преобразования; запись моно, запрашивает 32 кГц |
| Канонический контейнер | 13 МиБ символов |
| Вставка с пробелами/частями | 16 МиБ символов |
| Резервная копия | 262 144 символа |
| Контакты | 100; локальное имя до 64 символов |
| Пароль | до 1024 байт UTF-8 |
| Число частей | до 4096 |

МиБ означает 1 048 576 байт, КиБ — 1024 байта. Файл, размер растра и доступная структура аудио проверяются до декодирования. Недоверенные MIME/расширения не используются как единственное доказательство типа. Native-декодер браузера остаётся частью доверенной вычислительной базы; лимиты уменьшают риск исчерпания ресурсов, но не доказывают отсутствие ошибок в браузере.

## Проверки и статус совместимости

`npm test` выполняет модульные проверки протокола и ограничений. `npm run test:browser` запускает проверки интерфейса и локальной медиаобработки в Chromium. Перед распространением новой сборки выполните обе команды и зафиксируйте их результат. Успешный тест не равен независимому аудиту.

Подробности и границы — в [отчёте проверок](docs/TESTING.md). ## Файлы проекта

- `src/` — интерфейс, криптография, ключи/контакты, медиаобработка и Worker.
- `index.html` — русский интерфейс, доступные элементы управления и CSP.
- `public/` — собственные локальные иконки и PWA manifest.
- `scripts/build.mjs` — сборка esbuild, идентификатор версии и service worker с фиксированным списком файлов/хешей.
- `scripts/serve.mjs` — локальный статический предпросмотр, включая подпапку Pages.
- `tests/` — автоматические проверки.
- `.github/workflows/pages.yml` — проверки и публикация.
- `docs/FORMAT.md` — формат данных и криптографическая связь полей.
- `docs/SECURITY.md` — модель угроз, CSP, хранение, браузерные ограничения.
- `docs/MEDIA.md` — поддерживаемые структуры и ограничения медиа.
- `docs/TESTING.md` — фактически выполненные и оставшиеся ручные проверки.
- `public/THIRD-PARTY-NOTICES.txt` — лицензии включённых библиотек.

Сборка не добавляет дату/время в пользовательские контейнеры. Для воспроизводимости версии исходников используются отсортированные пути и содержимое исходников, сборочных скриптов, публичных файлов и lock-файла. Хеш, показанный тем же потенциально скомпрометированным сайтом, не является независимой гарантией подлинности.
